# RTMP 转 WebRTC 低延迟直播方案：编译文档

> 文档范围：`ngx-rtc-module` 从零到可运行的完整编译流程——第三方依赖（FFmpeg/libopus/libsrtp2）裁剪编译、OpenResty configure 与 gmake、addon `config` 脚本说明、部署与常见编译错误。命令均基于本机实际发生过并可复现的路径。
> 已与代码同步于 2026-09-09。

**结论摘要**：整个服务是一个静态链接的 OpenResty 进程。FFmpeg（仅 `aac` 解码器）、libopus、libsrtp2 均以静态库形式装入 `/home/dgliu/workspace/webrtc/third/{lib,include}`，再由 `ngx-rtc-module/config` 在 OpenResty configure 阶段经 `CORE_LIBS` 链入。编译主线只有两条命令：第三方 `configure && make && make install`（一次性），以及 `cd openresty-1.31.1.1 && gmake -j12 && gmake install`（增量）。历史踩坑集中在四条：FFmpeg 需 `--disable-x86asm/--disable-faan` 配合裁剪源码、libsrtp2 测试驱动 link 失败可忽略、纯 C 核心头文件漏包含导致常量未声明、OpenResty 用 `gmake`（GNU make）而非 BSD make。

## 2 第三方依赖裁剪编译

统一安装前缀为 `/home/dgliu/workspace/webrtc/third`。全部静态编译（`--disable-shared`/`--enable-static`），产物由 addon `config` 在链接期引用。

### 2.1 FFmpeg（仅 aac 解码，来源 SRS 的 ffmpeg-4-fit）

裁剪源码位于 SRS 6.0 发行树：`/home/dgliu/workspace/webrtc/srs-server-6.0-r1/trunk/3rdparty/ffmpeg-4-fit`。采用**外部构建目录** `/home/dgliu/workspace/webrtc/ffmpeg-build`（其 `config.h` 的 `FFMPEG_CONFIGURATION` 即为下方参数实录）。

```bash
cd /home/dgliu/workspace/webrtc/ffmpeg-build
/home/dgliu/workspace/webrtc/srs-server-6.0-r1/trunk/3rdparty/ffmpeg-4-fit/configure \
  --prefix=/home/dgliu/workspace/webrtc/third \
  --disable-everything --disable-programs --disable-doc --disable-network \
  --disable-asm --disable-x86asm --disable-inline-asm \
  --disable-avdevice --disable-avformat --disable-swscale --disable-postproc \
  --disable-avfilter --disable-avresample \
  --disable-dwt --disable-error-resilience --disable-lsp --disable-lzo \
  --disable-faan --disable-pixelutils \
  --disable-hwaccels --disable-devices --disable-iconv --disable-lzma --disable-sdl2 \
  --enable-decoder=aac --enable-swresample --enable-small \
  --enable-static --disable-shared --enable-pic
make -j12
make install
```

要点：`--disable-everything` 后只 `--enable-decoder=aac --enable-swresample`，保证静态库最小；`ngx_rtc_audio` 实际只用到 `avcodec`（aac 解码）、`avutil`、`swresample` 三个库。安装后 `third/lib` 出现 `libavcodec.a`、`libavutil.a`、`libswresample.a`（configure 摘要确认 enable 的库仅此三者）。

### 2.2 libopus 1.3.1

源码目录即 `/home/dgliu/workspace/webrtc/third/opus-1.3.1`（本机就地构建），configure 参数实录来自其 `config.log`。

```bash
cd /home/dgliu/workspace/webrtc/third/opus-1.3.1
./configure --prefix=/home/dgliu/workspace/webrtc/third
make -j12 && make install
```

安装后：`third/lib/libopus.a`，头文件 `third/include/opus/*.h`。`ngx_rtc_audio.c` 以 `#include <opus/opus.h>` 引用。

### 2.3 libsrtp2

本机 libsrtp2 构建目录事后已清理，安装产物保留为 `third/lib/libsrtp2.a` + `third/include/srtp2/`。标准流程（与实录日志一致，默认内部 crypto、`-fPIC`）：

```bash
# 假设解压于 <srtp-src>，configure 输出目录内就地构建
cd <srtp-src>
./configure --prefix=/home/dgliu/workspace/webrtc/third
make -j12            # 若测试驱动链接报错，见 §5.3
make install
```

若 `make` 在测试驱动链接处失败，可只构建并安装库本身：

```bash
make libsrtp2.a
install -D -m644 libsrtp2.a /home/dgliu/workspace/webrtc/third/lib/libsrtp2.a
cp -r include/srtp2 /home/dgliu/workspace/webrtc/third/include/
```

## 3 OpenResty configure 与 gmake

### 3.1 configure

在 OpenResty 源码树顶层执行。以下为最小可复现命令；`nginx -V` 输出中形如 `--add-module=../ngx_xxx` 的一长串模块参数由 OpenResty 自动追加（bundle 内 Lua/echo/memc 等组件），`--with-ld-opt=-Wl,-rpath,...,luajit/lib` 亦为自动生成。

```bash
cd /home/dgliu/workspace/webrtc/openresty-1.31.1.1
./configure \
  --prefix=/home/dgliu/workspace/webrtc/openresty-rtmp-new/nginx \
  --with-cc-opt=-O2 \
  --with-stream --with-stream_ssl_module --with-stream_ssl_preread_module \
  --with-http_ssl_module --with-http_v2_module --with-http_stub_status_module \
  --add-module=/home/dgliu/workspace/webrtc/nginx-http-flv-module \
  --add-module=/home/dgliu/workspace/webrtc/ngx-rtc-module
```

关键点：

- `--with-stream*` 必须开启：`ngx_rtc_stream_module` 是 `NGX_STREAM_MODULE`，依赖 stream 框架（`listen 8000 udp`）。
- `--with-http_ssl_module` 间接保证 OpenSSL 头文件与 `-lssl -lcrypto` 可用（DTLS/STUN HMAC 用）。
- `--add-module=.../ngx-rtc-module` 指向含 `config` 的目录；configure 期会打印 `adding module in .../ngx-rtc-module` 与 `ngx_rtc_module was configured`。

### 3.2 编译与安装

```bash
cd /home/dgliu/workspace/webrtc/openresty-1.31.1.1
gmake -j12
gmake install
```

`gmake install` 把二进制与默认配置安装到 `--prefix` 指定的 `/home/dgliu/workspace/webrtc/openresty-rtmp-new/nginx`。二次增量修改 RTC 源码后，只需重跑 `gmake -j12 && gmake install`。

### 3.3 安装验证

```bash

# configure arguments 中应出现：
#   --add-module=/home/dgliu/workspace/webrtc/nginx-http-flv-module
```

## 4 addon config 与部署

### 4.1 config 脚本结构

`ngx-rtc-module/config`（无扩展名，供 nginx `--add-module` 调用）分四段：

| 段 | 内容 | 作用 |
| --- | --- | --- |
| `RTC_CORE_SRCS/DEPS` | 10 个纯 C 单元（rtp/sdp/stun/dtls/srtp/audio/core/rtcp/hsm/session_fsm） | 追加到 `NGX_ADDON_SRCS/DEPS`，随所有模块编译 |
| `auto/module` 分支 | 三个 `ngx_module_*` 声明 + `. auto/module` | 按 `CORE/HTTP/STREAM` 三种类型注册 `ngx_rtmp_rtc_bridge_module`、`ngx_rtc_http_module`、`ngx_rtc_stream_module` |
| else 分支 | `CORE_MODULES/HTTP_MODULES/STREAM_MODULES` 直接赋值 | 兼容无 `auto/module` 的旧 nginx（本机走 `auto/module` 分支） |
| 链接与编译 | `CFLAGS += -I.../src -I.../third/include`；`CORE_LIBS += third/lib/*.a -lm -lpthread`；`USE_OPENSSL=YES` | 静态链入 FFmpeg/opus/srtp2 与系统 libm/pthread |

RTCP/HSM/session_fsm 三个源文件已加入 `RTC_CORE_SRCS/DEPS`（config 现为 10 个纯 C 单元），随所有模块一起编译进 nginx，无需额外落地点。

### 4.2 运行配置部署

编译安装后还需手动放置（或从模板复制）运行配置：

| 文件 | 路径 | 说明 |
| --- | --- | --- |
| 主配置（模板） | `openresty-rtmp-new/nginx/conf/nginx.conf` | rtmp(1935) + http(18082) + stream(8000 udp)，见架构设计 §4；`rtc_candidate_ip` 行为模板占位 |
| 运行配置（生成） | `openresty-rtmp-new/nginx/conf/nginx.rtc.conf` | `run.sh` 启动时由 `gen_nginx_conf` 自动探测主网卡 IP 后 sed 生成，nginx 实际以 `-c` 加载该文件 |
| Lua 鉴权 | `conf/auth.lua`、`rtmp_auth.lua`、`flv_auth.lua`、`config.lua`、`stream_keys.lua`、`admin_keys.lua` | 由 `lua_package_path "conf/?.lua;;"` 加载 |
| 启动脚本 | `/home/dgliu/workspace/webrtc/run.sh` | `start/nginx/push/stop/verify` 五个子命令；`push` 推流 URL 自动带 `?key=$PUSH_KEY` |

### 4.3 冒烟启动

```bash
cd /home/dgliu/workspace/webrtc
./run.sh nginx                    # 先 gen_nginx_conf 生成 conf/nginx.rtc.conf，再启动 nginx（RTMP 1935 / HTTP 18082 / UDP 8000）
ss -lntup | grep -E '1935|18082|8000'
tail -f openresty-rtmp-new/nginx/logs/error.log   # 应无 DTLS/SRTP init 失败日志
```

`run.sh nginx`/`start` 内部先执行 `gen_nginx_conf`：探测默认路由网卡 IPv4（可用环境变量 `RTC_CANDIDATE_IP` 覆盖）写进 `conf/nginx.rtc.conf`，nginx 以 `-p . -c conf/nginx.rtc.conf` 启动；`run.sh stop` 也先生成该文件以用同参数 `nginx -s stop` 幂等停机。

## 5 常见编译错误与排查

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 5.1 | FFmpeg configure 失败：`nasm/yasm not found` 或汇编相关报错 | ffmpeg-4-fit 默认探测 x86 asm，机器未装 nasm | 加 `--disable-asm --disable-x86asm --disable-inline-asm`（本机实录参数已含） |
| 5.2 | FFmpeg 裁剪源码 configure/link 报与 DCT/`faan` 相关符号 | 裁剪源未完整保留浮点 AAN DCT 等组件 | 显式 `--disable-faan`（连同 `--disable-dwt/--disable-lsp/--disable-lzo` 等一并关闭），见 §2.1 |
| 5.3 | libsrtp2 `make` 报 `libsrtp2.a(datatypes.o): multiple definition of 'bit_string'` 后 `collect2: error` | 仅**测试驱动**（`test/*_driver`）重复定义全局符号；`libsrtp2.a` 本身已正常产出 | 忽略该错误或只 `make libsrtp2.a` 并手动安装库与头（§2.3） |
| 5.4 | 编译 `ngx_rtc_http_module.c` 报 `'NGX_RTC_PAYLOAD_TYPE_H264' undeclared` | 该常量定义在 `ngx_rtc_rtp.h`，模块漏包含头文件（历史日志 build-rtc.log 实证） | 在引用常量/函数的 .c 中显式 `#include "ngx_rtc_rtp.h"`（当前源码已修复） |
| 5.5 | 链接报 `undefined reference` 到 `opus_*`/`avcodec_*`/`srtp_*` | addon `CORE_LIBS` 静态库顺序或漏 `-lm -lpthread` | 确认 `config` 中五个 `.a` 与 `-lm -lpthread` 全在 `CORE_LIBS`，且 `.a` 在依赖其的模块目标之后 |
| 5.6 | LuaJIT 构建输出 `**** WARNING Cannot determine rolling release version from git log` | 非错误，仅版本探测告警 | 忽略，不影响产物 |
| 5.7 | 运行时报 `dlopen(libluajit)`/加载 LuaJIT 失败 | 缺 `rpath` 指向部署前缀 luajit | 由 OpenResty configure 自动追加 `--with-ld-opt=-Wl,-rpath,...,luajit/lib`，不要手工删减 |
| 5.8 | `nginx -V` 无 stream 模块 / 运行报 `unknown directive "listen ... udp"` | configure 缺 `--with-stream` | 重跑 configure 时补上 `--with-stream --with-stream_ssl_module`（§3.1） |

排查顺序建议：先 `grep -iE "error:|undefined reference|multiple definition" *.log` 定位第一次真实失败；OpenResty 增量编译失败后不要直接 `gmake install`，先修错误再重编。
