# RTMP 转 WebRTC 低延迟直播方案：编译文档

> 文档范围：`nginx-rtc-example` 从零到可运行的完整编译流程——依赖拉取、第三方静态库（FFmpeg/libopus/libsrtp2）裁剪编译、OpenResty 装配编译、addon `config` 脚本说明、部署与常见编译错误。
> 构建脚本化：`setup.sh` 一键串起 fetch → build-deps → build-openresty。

**结论**：构建全链脚本化。三个脚本串成一条链：`scripts/fetch-deps.sh`（按钉死 ref 拉取全部依赖源到 `scripts/_cache`，不内嵌任何源码）→ `scripts/build-deps.sh`（把 FFmpeg/libsrtp2/opus 编成静态库装进 `build/third/{include,lib}`）→ `scripts/build-openresty.sh`（装配 OpenResty + 自研模块 + http-flv 编译，输出前缀 `build/nginx`）。一键入口 `scripts/setup.sh` 串起这三步。历史踩坑已内建进脚本：FFmpeg 需 `--disable-x86asm`（无 nasm）、libsrtp2 需 `CFLAGS=-fcommon`（gcc10+ 测试驱动多重定义）、opus 用 xiph 发行 tarball（git 树缺 `./configure`）。

## 1 结论与构建环境

### 1.1 目标产物

| 产物 | 位置 |
| --- | --- |
| 可执行 nginx（OpenResty，含自研 RTC 模块 + http-flv） | `build/nginx/nginx/sbin/nginx` |
| 运行配置（nginx.conf + Lua 鉴权，`run.sh` 同步） | `build/nginx/nginx/conf/` |
| 第三方静态库/头文件 | `build/third/lib`、`build/third/include` |
| 自研模块源码（构建时浅克隆钉 tag） | `build/src/nginx-rtc-module/` |
| http-flv 源码（构建时浅克隆钉 tag） | `build/src/nginx-http-flv-module/` |
| OpenResty 源码树（编译发生地） | `build/src/openresty-1.31.1.1/` |

说明：OpenResty 的 `--prefix` 约定会在 `build/nginx/` 下再落一层 `nginx/`（二进制与 conf 在其中），Lua 运行时（luajit/lualib）在 `build/nginx/` 顶层。

### 1.2 构建环境

| 项 | 值 |
| --- | --- |
| OS / 内核 | Ubuntu 22.04 x86_64（Linux 6.5） |
| 编译器 | gcc 11.4.0（`-O2`） |
| OpenSSL | 系统 3.0.2（nginx `built with OpenSSL 3.0.2`） |
| 底座 | OpenResty 1.31.1.1（bundle nginx-1.31.1，LuaJIT 2.1） |
| RTMP/HTTP-FLV | `nginx-http-flv-module` v1.2.14（构建时拉取） |
| RTC | `nginx-rtc-module` v0.4.0（自研公开仓，构建时拉取） |
| 第三方 | FFmpeg n6.1（aac 子集）/ libopus 1.3.1 / libsrtp2 2.3.0 |

### 1.3 构建顺序依赖

静态库必须先于 OpenResty configure 就绪，因为 `nginx-rtc-module/config` 在 configure 期经 `NGX_RTC_THIRD` 定位并引用 `third/lib` 的 `.a` 与 `third/include`。整体顺序：`fetch-deps（拉源）→ build-deps（编静态库）→ build-openresty（configure + make + install）→ run.sh nginx（部署启动）`。

## 2 依赖拉取与第三方裁剪编译

所有依赖源均由 `scripts/fetch-deps.sh` 按钉死 ref 拉取到 `scripts/_cache/`（gitignored），`scripts/build-deps.sh` 再从缓存编译。**仓库本身不内嵌任何 C 源码/二进制。**

### 2.1 fetch-deps.sh（拉源）

| 依赖 | 形式 | 钉死 ref |
| --- | --- | --- |
| nginx-rtc-module（自研 C 模块） | 浅克隆 tag | v0.4.0 |
| nginx-http-flv-module | 浅克隆 tag | v1.2.14 |
| libsrtp | 浅克隆 tag | v2.3.0 |
| FFmpeg | 浅克隆 tag | n6.1 |
| Opus | xiph 发行 tarball | 1.3.1 |
| OpenResty | openresty.org 发行 tarball | 1.31.1.1 |

github.com 被墙/劫持的主机需先 `export https_proxy=http://127.0.0.1:7890 HTTPS_PROXY=...`（脚本内 `gitc()` 显式传 `-c http.proxy`）。

### 2.2 FFmpeg（仅 aac 解码，n6.1 最小子集）

`build-deps.sh` 实际执行的 configure（等价参数实录）：

```bash
./configure --prefix="$THIRD" \
  --disable-everything \
  --enable-static --disable-shared --disable-programs --disable-doc --disable-network \
  --disable-x86asm \
  --enable-avcodec --enable-avutil --enable-swresample \
  --enable-decoder=aac --enable-decoder=aac_latm --enable-parser=aac
```

要点：`--disable-everything` 后只开 `avcodec/avutil/swresample` 三个库，`ngx_rtc_audio` 实际只用到 aac 解码 + 重采样 + 分配。`--disable-x86asm` 规避宿主机缺 nasm/yasm。安装后 `build/third/lib` 出现 `libavcodec.a`、`libavutil.a`、`libswresample.a`。

### 2.3 libopus 1.3.1

```bash
tar -xzf opus-1.3.1.tar.gz && cd opus-1.3.1
./configure --disable-shared --enable-static --disable-doc --prefix="$THIRD"
make -j"$JOBS" && make install
```

安装后：`lib/libopus.a` + `include/opus/*.h`；`ngx_rtc_audio.c` 以 `#include <opus/opus.h>` 引用。用 xiph 发行 tarball 而非 git 树：git 树只带 `autogen.sh/configure.ac`，缺生成的 `./configure`。

### 2.4 libsrtp2 2.3.0

```bash
CFLAGS="-fcommon" ./configure --prefix="$THIRD"
make -j"$JOBS" && make install
```

`-fcommon` 规避 gcc10+ 默认 `-fno-common` 下测试驱动里 `bit_string` 的多重定义（`libsrtp2.a` 本身不受影响，但 `make` 会连带编测试驱动而失败）。

### 2.5 就绪校验

```bash
ls build/third/lib/      # libavcodec.a libavutil.a libswresample.a libopus.a libsrtp2.a
ls build/third/include/  # libavcodec libavutil libswresample opus srtp2
```

## 3 OpenResty 装配编译（build-openresty.sh）

### 3.1 configure

`build-openresty.sh` 先把缓存里的两个 addon 拷入 `build/src/`，再在 OpenResty 源码树执行：

```bash
NGX_RTC_THIRD="$THIRD" ./configure \
  --prefix="$ORX" \
  --with-ld-opt="-Wl,-rpath,$ORX/luajit/lib" \
  --add-module="$MOD" \
  --add-module="$HFLV"
```

关键点：

- `--with-stream*` 由 OpenResty 默认携带（`ngx_rtc_stream_module` 是 `NGX_STREAM_MODULE`，依赖 stream 框架的 `listen 8000 udp`）。
- `--add-module="$MOD"` 指向含 `config` 的自研模块目录；configure 期打印 `adding module in .../nginx-rtc-module`。
- `NGX_RTC_THIRD` 显式传入，供模块 `config` 定位静态库（默认值在 `config` 里按 addon 相对路径推导，此处显式覆盖更稳）。

环境开关（均可不设，取默认）：

| 变量 | 作用 |
| --- | --- |
| `OPENRESTY_PREFIX` | 安装前缀，默认 `build/nginx` |
| `NGX_RTC_THIRD` | 已有预编译库时跳过 build-deps 重编 |
| `NGX_RTC_MODULE_SRC` | 本地模块工作副本（迭代模块时不 bump 钉 tag） |
| `OPENRESTY_SRC` | 已有 OpenResty 源码树（跳过 tarball 解包） |

### 3.2 编译与安装

```bash
make -j"$JOBS" && make install
```

`make install` 把二进制与默认配置装到 `--prefix` 指定的 `build/nginx`。二次迭代 RTC 源码后，重跑 `build-openresty.sh` 即可（模块源码走 `NGX_RTC_MODULE_SRC` 指向工作副本）。

### 3.3 安装验证

```bash
build/nginx/nginx/sbin/nginx -V
# configure arguments 中应出现：
#   --add-module=.../nginx-rtc-module
#   --add-module=.../nginx-http-flv-module
#   built with OpenSSL 3.0.2
```

## 4 addon config 与部署

### 4.1 config 脚本结构

`nginx-rtc-module/config`（无扩展名，供 nginx `--add-module` 调用；`ngx_addon_name=ngx_rtc_module`）分四段：

| 段 | 内容 | 作用 |
| --- | --- | --- |
| `RTC_CORE_SRCS/DEPS` | 纯 C 核心单元（rtp/sdp/stun/dtls/srtp/audio/core/rtcp/hsm/session_fsm/ring 等） | 追加到 `NGX_ADDON_SRCS/DEPS`，随所有模块编译 |
| `auto/module` 分支 | 四个 `ngx_module_*` 声明 + `. auto/module` | 注册 `ngx_rtc_core_module`（CORE）、`ngx_rtmp_rtc_bridge_module`（RTMP）、`ngx_rtc_http_module`（HTTP）、`ngx_rtc_stream_module`（STREAM） |
| else 分支 | `CORE_MODULES/HTTP_MODULES/STREAM_MODULES` 直接赋值 | 兼容无 `auto/module` 的旧 nginx |
| 链接与编译 | `CFLAGS += -I.../src -I$NGX_RTC_THIRD/include`；`CORE_LIBS += .../*.a -lm -lpthread`；`USE_OPENSSL=YES` | 静态链入 FFmpeg/opus/srtp2 与系统 libm/pthread |

### 4.2 运行配置部署

`run.sh nginx` 自动把 `deploy/nginx/{conf,html}` 同步进前缀并生成运行配置：

| 文件 | 路径 | 说明 |
| --- | --- | --- |
| 主配置（模板） | `deploy/nginx/conf/nginx.conf` | rtmp(1935) + http(18082) + stream(8000 udp)；`rtc_candidate_ip` 为占位 |
| 运行配置（生成） | `<prefix>/nginx/conf/nginx.rtc.conf` | `run.sh` 启动时 `gen_nginx_conf` 探测主网卡 IP 后 sed 生成，nginx 以 `-c` 加载 |
| Lua 鉴权 | `conf/auth.lua`、`rtmp_auth.lua`、`flv_auth.lua`、`config.lua`、`stream_keys.lua`、`admin_keys.lua` 等 | 由 `lua_package_path "conf/?.lua;;"` 加载 |
| 启动脚本 | `run.sh` | `nginx/push/keep-push/stop/verify` 子命令；推流 URL 自动带 HMAC `t`/`sign` |

### 4.3 冒烟启动

```bash
./run.sh nginx                 # sync deploy 配置 + gen_nginx_conf + 启动（1935/18082/8000 udp）
ss -lntup | grep -E '1935|18082|8000'
tail -f build/nginx/nginx/logs/error.log   # 应无 DTLS/SRTP init 失败日志
```

## 5 常见编译错误与排查

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 5.1 | FFmpeg configure 失败：`nasm/yasm not found` 或汇编相关报错 | 默认探测 x86 asm，机器未装 nasm | `--disable-x86asm`（build-deps.sh 已内置） |
| 5.2 | FFmpeg 裁剪源 configure/link 报与 DCT/`faan` 相关符号 | 裁剪源未完整保留浮点 AAN DCT 等组件 | 显式 `--disable-faan` 等一并关闭（旧 ffmpeg-4-fit 实录；n6.1 最小子集已无此问题） |
| 5.3 | libsrtp2 `make` 报 `libsrtp2.a(datatypes.o): multiple definition of 'bit_string'` 后 `collect2: error` | 仅**测试驱动**（`test/*_driver`）重复定义全局符号；`libsrtp2.a` 本身已正常产出 | 加 `CFLAGS="-fcommon"`（build-deps.sh 已内置） |
| 5.4 | 编译 `ngx_rtc_http_module.c` 报 `'NGX_RTC_PAYLOAD_TYPE_H264' undeclared` | 该常量定义在 `ngx_rtc_rtp.h`，模块漏包含头文件 | 在引用常量/函数的 .c 中显式 `#include "ngx_rtc_rtp.h"` |
| 5.5 | 链接报 `undefined reference` 到 `opus_*`/`avcodec_*`/`srtp_*` | addon `CORE_LIBS` 静态库顺序或漏 `-lm -lpthread` | 确认 `config` 中五个 `.a` 与 `-lm -lpthread` 全在 `CORE_LIBS`，且 `.a` 在依赖其的模块目标之后 |
| 5.6 | LuaJIT 构建输出 `**** WARNING Cannot determine rolling release version from git log` | 非错误，仅版本探测告警 | 忽略，不影响产物 |
| 5.7 | 运行时报 `dlopen(libluajit)`/加载 LuaJIT 失败 | 缺 `rpath` 指向部署前缀 luajit | build-openresty.sh 已显式 `--with-ld-opt=-Wl,-rpath,$ORX/luajit/lib` |
| 5.8 | `nginx -V` 无 stream 模块 / 运行报 `unknown directive "listen ... udp"` | configure 缺 `--with-stream` | OpenResty 默认已带 `--with-stream`；自定义底座需自行补上 |

排查顺序建议：先 `grep -iE "error:|undefined reference|multiple definition" build/src/*/*.log 2>/dev/null` 定位第一次真实失败；OpenResty 增量编译失败后不要直接 `make install`，先修错误再重编。
