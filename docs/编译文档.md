# RTMP 转 WebRTC 低延迟直播方案：编译文档

> 范围：`nginx-rtc-example` 从依赖拉取到可运行 nginx 的完整构建链，以及 Windows（MSYS2 原生）构建。

**结论**：构建全链脚本化。`scripts/setup.sh` 串起 `fetch-deps.sh` → `build-deps.sh` → `build-openresty.sh`，分发再用 `package-linux-src.sh`。依赖按钉死 ref 拉到 `scripts/_cache/`（gitignored），仓库不内嵌第三方源码或二进制。产物是可执行 nginx（OpenResty + 自研 RTC 模块 + http-flv）、第三方静态库与运行配置。Windows 用 MSYS2 原生编译，只提供 RTMP → HTTP-FLV/HLS/DASH，不含 WebRTC 媒体面。

## 1 产物与环境

- nginx（OpenResty + RTC 模块 + http-flv）：`build/nginx/nginx/sbin/nginx`
- 运行配置（nginx.conf + Lua 鉴权）：`build/nginx/nginx/conf/`
- 第三方静态库/头文件：`build/third/{lib,include}`
- 构建期浅克隆的模块源码：`build/src/nginx-rtc-module/`、`build/src/nginx-http-flv-module/`

环境：Ubuntu 22.04 x86_64，gcc 11.4（`-O2`）；系统 OpenSSL 3.0.2（`nginx -V` 显示 `built with OpenSSL 3.0.2`）。OpenResty 的 `--prefix` 约定会在 `build/nginx/` 下再落一层 `nginx/`（二进制与 conf 在其中），LuaJIT/lualib 在 `build/nginx/` 顶层。

## 2 构建链与脚本顺序

静态库必须先于 OpenResty configure 就绪：addon `config` 在 configure 期经 `NGX_RTC_THIRD` 引用 `third/lib` 的 `.a` 与 `third/include`。

```
scripts/setup.sh             # = fetch-deps + build-deps + build-openresty
scripts/fetch-deps.sh        # 按钉死 ref 拉源到 scripts/_cache/
scripts/build-deps.sh        # 编 FFmpeg/opus/libsrtp2 静态库到 build/third/
scripts/build-openresty.sh   # configure + make + make install -> build/nginx/
scripts/package-linux-src.sh # 打源码分发包 dist/nginx-rtc-example-<ver>-src.tar.gz
```

### 2.1 fetch-deps.sh

| 依赖 | 形式 | 钉死 ref |
| --- | --- | --- |
| nginx-rtc-module | 浅克隆 tag | v0.4.0 |
| nginx-http-flv-module | 浅克隆 tag | v1.2.14 |
| libsrtp | 浅克隆 tag | v2.3.0 |
| FFmpeg | 浅克隆 tag | n6.1 |
| Opus | xiph 发行 tarball | 1.3.1 |
| OpenResty | openresty.org tarball | 1.31.1.1 |

github.com 被墙时先 `export https_proxy=http://127.0.0.1:7890 HTTPS_PROXY=...`；脚本内 `gitc()` 显式传 `-c http.proxy`。

### 2.2 build-deps.sh

FFmpeg（n6.1，只开 aac 解码）：

```bash
./configure --prefix="$THIRD" --disable-everything --disable-x86asm \
  --enable-static --disable-shared --disable-programs --disable-doc --disable-network \
  --enable-avcodec --enable-avutil --enable-swresample --enable-decoder=aac --enable-parser=aac
```

libopus 1.3.1 / libsrtp2 2.3.0：

```bash
./configure --disable-shared --enable-static --disable-doc --prefix="$THIRD"  # opus
CFLAGS="-fcommon" ./configure --prefix="$THIRD"                                # libsrtp2
make -j"$JOBS" && make install
```

### 2.3 build-openresty.sh

```bash
NGX_RTC_THIRD="$THIRD" ./configure --prefix="$ORX" \
  --with-ld-opt="-Wl,-rpath,$ORX/luajit/lib" \
  --add-module="$MOD" --add-module="$HFLV"
make -j"$JOBS" && make install
```

`--with-stream*` 由 OpenResty 默认携带；`--add-module` 指向含 `config` 的模块目录。环境变量（均可不设，取默认）：`OPENRESTY_PREFIX`（安装前缀，默认 `build/nginx`）、`NGX_RTC_THIRD`（预编译第三方库树，跳过 build-deps 重编）、`NGX_RTC_MODULE_SRC`（本地模块工作副本，迭代时不 bump 钉 tag）、`OPENRESTY_SRC`（已有 OpenResty 源码树，跳过 tarball 解包）、`JOBS`（make 并行度，默认 nproc）。验证：`build/nginx/nginx/sbin/nginx -V` 的 configure arguments 应含两个 `--add-module`。

## 3 addon config 契约

`nginx-rtc-module/config`（无扩展名，`ngx_addon_name=ngx_rtc_module`）注册四个模块并编译纯 C 核心：

| 段 | 内容 |
| --- | --- |
| `RTC_CORE_SRCS/DEPS` | 纯 C 核心（rtp/sdp/stun/dtls/srtp/core/ring/jitter/audio/audio_worker/rtcp/avsync/hsm/session_fsm/shm），追加到 `NGX_ADDON_SRCS/DEPS` |
| `auto/module` 分支 | 四个模块声明 + `. auto/module`：`ngx_rtc_core_module`(CORE)、`ngx_rtmp_rtc_bridge_module`(CORE)、`ngx_rtc_http_module`(HTTP)、`ngx_rtc_stream_module`(STREAM)；无 `auto/module` 的旧 nginx 走 else 分支直接赋值 `CORE_MODULES/HTTP_MODULES/STREAM_MODULES` |
| 链接与编译 | `CFLAGS += -DNGX_RTC_EVENT_LOOP -I.../src -I$NGX_RTC_THIRD/include`；`CORE_LIBS += 五个 .a -lm -lpthread`；`USE_OPENSSL=YES` |

## 4 运行配置与部署

`run.sh nginx` 把 `deploy/nginx/{conf,html}` 同步进前缀，探测主网卡 IP 后 sed 生成 `nginx.rtc.conf` 并以 `-c` 启动（rtmp 1935 / http 18082 / stream 8000 udp）。模板 `deploy/nginx/conf/nginx.conf` 的 `rtc_candidate_ip` 为占位，可用 `RTC_CANDIDATE_IP` 覆盖；推流 URL 自动带 HMAC `t`/`sign`。子命令：`sync|nginx|start|push|transcode|keep-push|keep-transcode|stop|verify|ngxtop`。

```bash
./run.sh nginx                 # sync + gen nginx.rtc.conf + 启动
tail -f build/nginx/nginx/logs/error.log   # 应无 DTLS/SRTP init 失败
```

## 5 sanitizer 构建

`scripts/e2e-asan.sh` 需要一个 ASan 版 OpenResty，默认前缀 `build/nginx-asan/nginx`（位置参数可覆盖）。两个环境变量叠加：`EXTRA_CC_OPT` 追加 `--with-cc-opt`，须含 `-fsanitize=...` 与 `-O1`（OpenResty 自带 `-O2` 在前，须 `-O1` 才压低优化）；`EXTRA_LD_OPT` 追加 `--with-ld-opt`，须含 `-fsanitize=...`（nginx 链接行不含 CFLAGS，只给 cc-opt 会报 `undefined reference to __asan_*`）。

整条构建须套 `setarch $(uname -m) -R` 关 ASLR：configure 会编译并运行探测程序，ASLR 开着时 ASan 影子映射冲突循环 `AddressSanitizer:DEADLYSIGNAL`，被误报成 `can not detect long size`。第三方 UBSan 噪声用 `-fno-sanitize=alignment -fno-sanitize=nonnull-attribute` 编译期关掉；构建期设 `ASAN_OPTIONS=detect_leaks=0`。

```bash
setarch $(uname -m) -R env ASAN_OPTIONS=detect_leaks=0 \
  NGX_RTC_MODULE_SRC=$PWD/../nginx-rtc-module OPENRESTY_PREFIX=$PWD/build/nginx-asan \
  EXTRA_CC_OPT="-fsanitize=address,undefined -fno-sanitize=alignment -fno-sanitize=nonnull-attribute -fno-omit-frame-pointer -O1" \
  EXTRA_LD_OPT="-fsanitize=address,undefined" scripts/build-openresty.sh
```

## 6 Windows（MSYS2 原生编译）

Windows nginx 不支持动态加载 C 模块（无 `--add-dynamic-module`），OpenResty 官方二进制也不含两个模块，须从源码把 `nginx-rtc-module` 与 `nginx-http-flv-module` 静态编入 `nginx.exe`。编译须在 Windows 上的 MSYS2 MINGW64 内原生进行；网络受限时先 `export https_proxy=http://127.0.0.1:7890`。

环境检查（用 MSYS2 MINGW64 快捷方式，不要用 MSYS2 MSYS）：

```bash
echo $MSYSTEM      # 应为 MINGW64
gcc -dumpmachine   # 应为 x86_64-w64-mingw32
make --version     # GNU Make
perl -v            # 能输出版本
```

一键编译 `scripts/build-win64-msys2.sh`（在 MINGW64 内执行），对应 OpenResty 上游 `util/build-win32.sh` 流程加两个模块：

1. pacman 装 mingw64 工具链与 `libopus`/`libsrtp`（不装完整 ffmpeg）。
2. 下载 OpenResty 1.31.1.1 + OpenSSL 3.5.6 / zlib 1.3.2 / PCRE2 10.47，浅克隆 FFmpeg n8.0。
3. 克隆 `nginx-rtc-module`（分支 `win32-compat`，可用 `NGX_RTC_MODULE_SRC` 覆盖）与 `nginx-http-flv-module` v1.2.14。
4. 给 http-flv 打 `int8_t` 补丁：`ngx_rtmp.h` 的 `#if (NGX_WIN32)` 收窄为 `#if (NGX_WIN32 && defined(_MSC_VER))`。
5. 从 n8.0 源码编只含 AAC 的动态库 FFmpeg（`--enable-shared --disable-static`），避免拖入完整编解码器 DLL。
6. 合成混合三方目录 `build-win64/third`（FFmpeg `*.dll.a` + pacman 的 `libopus.dll.a`/`libsrtp2.dll.a`）。
7. `NGX_RTC_THIRD=build-win64/third` 跑 configure（官方 Windows 参数 + `--add-module`，含 `--with-select_module`、`-DFD_SETSIZE=1024`）。
8. `make && make install`，再从 `nginx.exe` 导入表递归收集运行时 DLL。

输出布局：编译落在 `build-win64/openresty-win64/`（`nginx.exe`、`lua51.dll`、`conf/`、`html/`、`lua/` 与依赖 DLL）。可分发包位于 `dist/win64-package/`，含 `nginx.exe`、运行时 DLL（`lua51.dll`、`libcrypto-3-x64.dll`、`libopus-0.dll`、`libsrtp2-1.dll`、`libwinpthread-1.dll`）、`conf/`、`html/`、`tools/ffmpeg.exe`、`start.bat`/`stop.bat`/`push_test.bat` 与 `README.md`；另有 `dist/nginx-rtc-win64.zip`。

运行：

```cmd
cd dist\win64-package
start.bat              :: 或 nginx.exe -p .
push_test.bat          :: 用内置 ffmpeg.exe 推 live/livestream
stop.bat               :: 或 nginx.exe -s stop
```

`tools/ffmpeg.exe` 为内置推流工具，`push_test.bat` 直接调用，无需另装 ffmpeg。

推流端连 RTMP 1935；播放端访问 `http://127.0.0.1:18082/flvplayer`，或拉 `http://127.0.0.1:18082/live?app=live&stream=STREAM`、`/hls/STREAM.m3u8`、`/dash/STREAM.mpd`。防火墙只需放行 TCP 1935 与 TCP 18082。包内推流/播放鉴权默认关闭；如需开启，取消 `conf/nginx.conf` 中 `on_publish` 与 `access_by_lua_file conf/flv_auth.lua` 的注释，并按 HMAC `t`/`sign` 规则签名。

已知限制：

- Windows nginx 无 UDP，WebRTC 媒体面（UDP 8000）不可用；包只提供 RTMP → HTTP-FLV/HLS/DASH，且推流/播放鉴权默认关闭。
- 仅支持 `select` 事件模型、单 worker，适合开发验证，不适合高并发生产。
- 并发连接默认上限 1024（`--with-cc-opt='-DFD_SETSIZE=1024'`）。
- Linux MinGW 完整 `nginx.exe` 交叉构建阻塞：`lua-resty-signal-0.04/resty_signal.c` 使用 `SIGURG`，交叉目标下未定义（`error: 'SIGURG' undeclared`）。MSYS2 原生路径不受影响。

## 7 常见编译错误与排查

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| fetch-deps 拉取 github 超时/被重置 | 网络不可达 | 先 `export https_proxy=http://127.0.0.1:7890`；脚本 `gitc()` 已显式传 `-c http.proxy` |
| `third libs missing under ... - run build-deps.sh or set NGX_RTC_THIRD` | 静态库未就绪 | 跑 `scripts/build-deps.sh`，或用 `NGX_RTC_THIRD` 指向已有树 |
| LuaJIT 输出 `**** WARNING Cannot determine rolling release version from git log` | 非错误，版本探测告警 | 忽略，不影响产物 |
| 运行时报 `dlopen(libluajit)` 失败 | 缺 rpath 指向部署前缀 luajit | build-openresty.sh 已带 `--with-ld-opt=-Wl,-rpath,$ORX/luajit/lib` |
| 链接报 `undefined reference` 到 `opus_*`/`avcodec_*`/`srtp_*` | addon `CORE_LIBS` 漏库或顺序错 | 确认五个 `.a` 与 `-lm -lpthread` 全在 `CORE_LIBS` |
| `nginx -V` 无 stream 模块 / 运行报 `unknown directive "listen ... udp"` | configure 缺 `--with-stream` | OpenResty 默认已带；自定义底座需补上 |
| ASan build: configure 报 `can not detect long size` | 未关 ASLR，ASan 影子映射冲突 | 用 `setarch $(uname -m) -R` 包整条构建 |
| ASan build: 链接报 `undefined reference to __asan_*` | 只给 `EXTRA_CC_OPT` 没给 `EXTRA_LD_OPT` | 两者都带 `-fsanitize=...` |
